# 三阶原型锚点系统

## 概述

原型锚点是表达审计的"假设生成 → 验证 → 确认"循环。不是给被访谈者贴标签，而是通过三阶迭代逐步精炼对表达人格的理解。

**注意：** 12 种表达人格原型的具体定义由用户单独设计（你提到正在设计表达者原型系统）。本文件定义锚点的触发时机、验证逻辑和输出格式。

## 三阶锚点

### 锚点 1：假设形成（D0 完成后）

**时机：** D0 的 18 题全部答完。

**触发条件：**
- D0 的 progress.status 变为 "complete"
- rawData 中 Q1-Q18 全部有 answer

**输入数据：**
- Q1-Q6：北极星溯源链（身份认同来源）
- Q7-Q12：领域定位（表达发生的语境）
- Q13-Q18：身份陈述（核心身份关键词）

**处理逻辑：**
1. 分析北极星溯源链，识别被访谈者的"原始素材"——哪些深层影响源在回答中被提及
2. 提取身份陈述中的核心关键词（从 Q13-Q18）
3. 对照原型系统的候选列表，形成 1-2 个初步假设
4. 记录假设、支持证据、不确定之处

**输出：**
```json
{
  "anchor1": {
    "status": "hypothesis_formed",
    "hypothesis": "候选原型 A（阶段 L1）",
    "evidence": ["Q1: 最欣赏的表达者是xxx", "Q6: 溯源链中意外的名字是xxx"],
    "contradictions": [],
    "timestamp": "2026-08-19T..."
  }
}
```

**重要规则：**
- 锚点 1 的假设是试探性的，必须标注"阶段 L1"
- 不锁定——明确告诉被访谈者这是"初步假设，可能在后面被修正"
- 不确定之处必须记录，不能为了整洁而忽略

---

### 锚点 2：假设精炼（D2 完成后）

**时机：** D0 + D1 + D2 全部答完。

**触发条件：**
- D0、D1、D2 的 progress.status 全部为 "complete"
- 锚点 1 已形成（status 为 "hypothesis_formed"）

**输入数据：**
- D0-D2 的全部原始数据
- 锚点 1 的假设和证据
- D1 和 D2 中检测到的所有张力

**处理逻辑：**
1. 用 D1（信念体系）验证锚点 1 的假设——信念数据是否支持原型候选？
2. 用 D2（表达机制）验证锚点 1 的假设——表达方式是否匹配原型特征？
3. 检查 D1-D2 中的张力是否挑战了假设
4. 如果验证通过 → 升级为阶段 L2
5. 如果验证失败 → pivot 到第二个候选原型，或标记为"待定"

**验证矩阵：**

| 锚点 1 候选 | D1 验证信号 | D2 验证信号 | 通过条件 |
|---|---|---|---|
| 反叛者 | Q19 有强烈反共识立场 | Q45 有禁忌词、Q36 有刻意不带的内容 | 两者都有 → L2 |
| 探索者 | Q23 有跨领域启发 | Q39 有跨领域形式借鉴 | 两者都有 → L2 |
| 英雄 | Q20 有明确的辩护立场 | Q35 以观点为主、Q37 快速多观点 | 两者都有 → L2 |
| 智者 | Q25 质疑底层假设 | Q46 以提问开头 | 两者都有 → L2 |
| 创造者 | Q22 有信念驱动的表达转变 | Q48 有强烈句式偏好 | 两者都有 → L2 |
| 护理者 | Q10 有明确的受众关怀 | Q35 以故事/提问为主 | 两者都有 → L2 |

**输出：**
```json
{
  "anchor2": {
    "status": "confirmed | pivoted | pending",
    "hypothesis": "候选原型 A（阶段 L2）或 B（阶段 L2）",
    "evidence": ["Q19: 反共识立场", "Q45: 禁忌词列表"],
    "contradictions": ["T7: Q19 vs Q21"],
    "pivotReason": "如果 pivoted，记录原因",
    "timestamp": "2026-08-19T..."
  }
}
```

**重要规则：**
- 如果 pivot，必须在 tensionLog 中记录 pivot 原因
- 不要求 100% 确认——L2 阶段允许"大概率是这个，但有待验证"
- 如果无法确认（两个候选都证据不足），标记为"待定"，等待锚点 3

---

### 锚点 3：最终确认（全部完成后）

**时机：** 所有已完成模块的题目全部答完。

**触发条件：**
- 当前模式的所有题目状态为 "answered"
- 锚点 2 已完成（status 不为 "pending"）

**输入数据：**
- 全部原始数据（95 题）
- 锚点 1 和锚点 2 的假设历史
- 全部张力日志
- 核心身份陈述

**处理逻辑：**
1. 用全部数据验证锚点 2 的假设
2. 检查是否出现新的矛盾
3. 确认、修正或推翻锚点 2 的假设
4. 生成最终原型评估报告

**输出：**
```json
{
  "anchor3": {
    "status": "confirmed | revised | rejected",
    "hypothesis": "最终原型（阶段 L3）",
    "primary": "反叛者",
    "secondary": "探索者",
    "evidence": ["全部 95 题的关键证据摘要"],
    "contradictions": ["T7: 已解决", "T10: 已解决"],
    "confidence": "high | moderate",
    "timestamp": "2026-08-19T..."
  }
}
```

**重要规则：**
- 允许最终确认时添加"次要原型"——一个人的表达人格很少是单一的
- 置信度标注必须诚实——如果数据不足，标注"moderate"而非"high"
- 所有张力必须标记为"已解决"或"保留"——不能有未处理的张力进入最终报告

## 原型评估在报告中的位置

### 快速报告
不包含原型评估。数据不足，不做假设。

### 核心报告
包含锚点 1 的初步假设（阶段 L1），标注"初步，建议完成深度模式后复核"。

### 深度报告
包含锚点 3 的最终评估（阶段 L3），标注置信度，含主要原型和次要原型。

## 与模块的集成

### 模块运行时的原型检查

在每个模块结束时，系统应该：

1. 检查是否到达锚点触发时机
2. 如果到达 → 执行锚点逻辑
3. 将结果写入状态文件
4. 在下一题之前向被访谈者展示锚点结果

### 锚点展示话术

**锚点 1 展示（D0 完成后）：**
```
D0 完成了。基于你刚刚说的这些，我有一个初步的观察——

你身上有一种 [原型名称] 的特质。不是说你『就是』这个原型，
而是说你的表达方式里有这种气质。

这个判断还很不精确——它在 D1 和 D2 之后可能会变。
但我想先告诉你，看看你的反应。
```

**锚点 2 展示（D2 完成后）：**
```
现在我们已经有了 D0-D2 的数据。
之前的初步假设有了一些变化——

[确认/pivot/待定的说明]

这个判断比 D0 结束时准确了一些，但还不是最终版。
要等全部完成后才能确认。
```

**锚点 3 展示（全部完成后）：**
```
全部完成了。基于 95 道题的完整数据，
我对你的表达人格有一个比较确信的判断——

[最终原型评估]

这个判断的置信度是 [高/中]。
[如果有次要原型] 你还有一个次要原型 [名称]，
它在 [哪些场景] 下会出现。
```

## 原型评估的输出格式

### 核心报告中的原型评估

```markdown
## 原型评估（初步）

**主要原型：** [名称]（阶段 L1）

**判断依据：**
- [来自 Q1/Q6 的证据]
- [来自 Q19/Q20 的证据]

**不确定之处：**
- [需要 D2/D3 数据验证的地方]

⚠️ 这是基于 D0 的初步假设，建议完成深度模式后复核。
```

### 深度报告中的原型评估

```markdown
## 原型评估（复核后）

**主要原型：** [名称]（阶段 L3）
**次要原型：** [名称]（阶段 L3）
**置信度：** [高/中]

**判断依据：**
- [来自 D0 的关键证据]
- [来自 D1 的关键证据]
- [来自 D2 的关键证据]
- [来自 D3/D7 的关键证据]

**次要原型的出现场景：**
- [在什么情况下次要原型会浮现]

**已被解决的张力：**
- [T7: ...] → [解决方案]
- [T10: ...] → [解决方案]

**保留的张力：**
- [T21: ...] → [为什么保留]
```

## 原型 pivot 规则

当锚点 2 或锚点 3 需要 pivot 时：

1. **必须在 tensionLog 中记录 pivot 原因**
2. **必须在输出中说明从什么 pivot 到什么**
3. **如果 pivot 和被访谈者的自我认知冲突 → 优先信任被访谈者的自我认知**
4. **如果 pivot 是因为数据不足 → 标记为"待定"，不强行确认**

## 与表达者原型系统的衔接

用户正在单独设计表达者原型系统（12 种表达人格原型）。本文件定义的锚点逻辑将与该系统的具体原型定义对接：

- 锚点 1-3 中的"候选原型"引用表达者原型系统中的具体原型名称
- 验证矩阵中的"验证信号"将根据表达者原型系统的具体定义调整
- 最终输出格式中的"主要原型/次要原型"将使用表达者原型系统的命名

**本文件只定义逻辑框架，不定义具体原型。具体原型由表达者原型系统提供。**
