# 三阶原型锚点系统

## 概述

原型锚点是表达审计的「假设生成 → 验证 → 精炼」循环。**不是**给被访谈者贴永久标签。

### 硬限制（口径修复）

| 项 | 状态 |
|----|------|
| 本文件 | 只定义**时机、输入、输出字段、置信标注** |
| 十二型 / 表达人格词典 | **未入库**；仓库内不存在权威类型表 |
| 对外话术 | 锚点结论必须标 `hypothesis_only` 或「初步假设」 |
| 禁止 | 「你的类型是 X（已确认）」——在词典入库并完成 L3 证据规则前一律禁止 |
| 无词典时 L3 | 最多输出「结构主题摘要 + 张力」，**不要**发明类型名 |

若日后加入 `proto-system/archetypes.md`，再允许对照命名；在那之前，编译器审计报告的「原型评估」节应写：`insufficient_dictionary`。

**历史说明：** 曾规划 12 种表达人格由设计者另表提供；在表进入本仓库前，锚点系统降级为**假设日志**。

## 三阶锚点

### 锚点 1：假设形成（D0 完成后）

**时机：** D0 的 18 题全部答完。

**触发条件：**
- D0 的 progress.status 变为 "complete"
- rawData 中 Q1-Q18 全部有 answer

**输入数据：**
- Q1-Q6：北极星溯源链（身份认同来源）
- Q7-Q12：领域定位（表达发生的语境）
- Q13-Q18：身份陈述（核心身份关键词）

**处理逻辑：**
1. 分析北极星溯源链，识别被访谈者的"原始素材"——哪些深层影响源在回答中被提及
2. 提取身份陈述中的核心关键词（从 Q13-Q18）
3. 无词典时不要对照类型表；只形成 1–2 个**结构主题**假设（hypothesis_only）
4. 记录假设、支持证据、不确定之处；禁止填写类型名

**输出：**
```json
{
  "anchor1": {
    "status": "hypothesis_formed",
    "hypothesis": "结构主题：把困惑公开（hypothesis_only，无类型名）",
    "evidence": ["Q1: 最欣赏的表达者是xxx", "Q6: 溯源链中意外的名字是xxx"],
    "contradictions": [],
    "timestamp": "2026-08-19T..."
  }
}
```

**重要规则：**
- 锚点 1 的假设是试探性的，必须标注"阶段 L1"
- 不锁定——明确告诉被访谈者这是"初步假设，可能在后面被修正"
- 不确定之处必须记录，不能为了整洁而忽略

---

### 锚点 2：假设精炼（D2 完成后）

**时机：** D0 + D1 + D2 全部答完。

**触发条件：**
- D0、D1、D2 的 progress.status 全部为 "complete"
- 锚点 1 已形成（status 为 "hypothesis_formed"）

**输入数据：**
- D0-D2 的全部原始数据
- 锚点 1 的假设和证据
- D1 和 D2 中检测到的所有张力

**处理逻辑（无词典）：**
1. 用 D1 信念检查锚点 1 的**结构主题**是否仍站得住
2. 用 D2 机制检查表达方式是否与该主题一致
3. 看 tensionLog 是否挑战该主题
4. 站得住 → 升为 L2，仍标 `hypothesis_only`
5. 站不住 → 改写主题或 `pending`；**不要**换成类型名

类型对照表在 `proto-system/archetypes.md` 入库前不存在，禁止在话术或报告里使用类型名。

**输出：**
```json
{
  "anchor2": {
    "status": "confirmed | pivoted | pending",
    "hypothesis": "结构主题对照（hypothesis_only；无词典则不写类型名）",
    "evidence": ["Q19: 反共识立场", "Q45: 禁忌词列表"],
    "contradictions": ["T7: Q19 vs Q21"],
    "pivotReason": "如果 pivoted，记录原因",
    "timestamp": "2026-08-19T..."
  }
}
```

**重要规则：**
- 如果 pivot，必须在 tensionLog 中记录 pivot 原因
- 不要求 100% 确认——L2 阶段允许"大概率是这个，但有待验证"
- 如果无法确认（两个候选都证据不足），标记为"待定"，等待锚点 3

---

### 锚点 3：最终确认（全部完成后）

**时机：** 所有已完成模块的题目全部答完。

**触发条件：**
- 当前模式的所有题目状态为 "answered"
- 锚点 2 已完成（status 不为 "pending"）

**输入数据：**
- 全部原始数据（95 题）
- 锚点 1 和锚点 2 的假设历史
- 全部张力日志
- 核心身份陈述

**处理逻辑：**
1. 用全部数据验证锚点 2 的假设
2. 检查是否出现新的矛盾
3. 确认、修正或推翻锚点 2 的假设
4. 生成最终原型评估报告

**输出：**
```json
{
  "anchor3": {
    "status": "confirmed | revised | rejected",
    "hypothesis": "最终原型（阶段 L3）",
    "primary": "反叛者",
    "secondary": "探索者",
    "evidence": ["全部 95 题的关键证据摘要"],
    "contradictions": ["T7: 已解决", "T10: 已解决"],
    "confidence": "high | moderate",
    "timestamp": "2026-08-19T..."
  }
}
```

**重要规则：**
- 允许最终确认时添加"次要原型"——一个人的表达人格很少是单一的
- 置信度标注必须诚实——如果数据不足，标注"moderate"而非"high"
- 所有张力必须标记为"已解决"或"保留"——不能有未处理的张力进入最终报告

## 原型评估在报告中的位置

### 快速报告
不包含原型评估。数据不足，不做假设。

### 核心报告
包含锚点 1 的 **hypothesis_only** 结构摘要（阶段 L1）。无词典时不写类型名。标注「初步，建议完成深度模式后复核」。

### 深度报告
包含锚点 3 的结构主题 + 张力复核（阶段 L3）。无 `proto-system/archetypes.md` 时仍禁止确认类型名，最多 `insufficient_dictionary`。

## 与模块的集成

### 模块运行时的原型检查

在每个模块结束时，系统应该：

1. 检查是否到达锚点触发时机
2. 如果到达 → 执行锚点逻辑
3. 将结果写入状态文件（`hypothesis_only`）
4. **不要**为展示锚点额外再问一题；一句观察即可，然后停，等用户。禁止发明类型名。

### 锚点展示话术

无词典时只陈述**结构主题与张力**，所有结论标 `hypothesis_only`。

**锚点 1 展示（D0 完成后）：**
```
D0 这块先收到这里。我有一个初步观察（hypothesis_only，不是类型诊断）——

反复出现的结构是：[从回答里抽出的主题，例如「把困惑公开」]。
和它拉着的张力是：[tensionLog 里已有的对照]。

这不是人格标签，后面还可能改。你要先回应这句观察，还是继续下一块？
```

**锚点 2 展示（D2 完成后）：**
```
D0–D2 之后，刚才那条观察有一点变化（仍是 hypothesis_only）——

[结构主题如何变 / 哪条张力还在]

没有类型名。要等全部完成、并且有词典，才能对照命名。
```

**锚点 3 展示（全部完成后）：**
```
提纲覆盖完了。基于现有回答的结构摘要（hypothesis_only）：

- 反复主题：[…]
- 仍未闭合的张力：[…]

仓库里还没有原型词典，所以我不会给你一个「确认类型」。
需要的话可以写进审计报告的「原型评估」节，标 insufficient_dictionary。
```

## 原型评估的输出格式

### 核心报告中的原型评估

```markdown
## 原型评估（初步，hypothesis_only）

**状态：** insufficient_dictionary（无十二型词典，不输出类型名）

**结构主题：** [从回答抽出的 1–2 个主题]

**判断依据：**
- [来自 Q1/Q6 的证据]
- [来自 Q19/Q20 的证据]

**不确定之处：**
- [需要 D2/D3 数据验证的地方]

⚠️ 初步假设，不是确认人格类型。建议完成深度模式后复核。
```

### 深度报告中的原型评估

```markdown
## 原型评估（复核后，hypothesis_only）

**状态：** insufficient_dictionary（词典入库前禁止确认类型名）
**结构主题：** […]
**置信度：** [preliminary / moderate]（无词典时不得标「已确认」）

**判断依据：**
- [来自 D0 的关键证据]
- [来自 D1 的关键证据]
- [来自 D2 的关键证据]
- [来自 D3/D7 的关键证据]

**已被解决的张力：**
- [T7: ...] → [如何被后来的回答照亮]

**保留的张力：**
- [T21: ...] → [为什么不抹平]
```

## 原型 pivot 规则

当锚点 2 或锚点 3 需要 pivot 时：

1. **必须在 tensionLog 中记录 pivot 原因**
2. **必须在输出中说明从什么 pivot 到什么**
3. **如果 pivot 和被访谈者的自我认知冲突 → 优先信任被访谈者的自我认知**
4. **如果 pivot 是因为数据不足 → 标记为"待定"，不强行确认**

## 与表达者原型系统的衔接

十二型词典**尚未入库**。在 `proto-system/archetypes.md` 存在之前：

- 锚点只输出结构主题 + 张力，标 `hypothesis_only`
- 上方验证矩阵里的类型名是**休眠示例**，禁止写进对用户的话术或审计报告
- 不得输出「主要原型 / 次要原型」确认名

词典入库后再允许对照命名。本文件只定义时机与字段，不定义具体原型。
