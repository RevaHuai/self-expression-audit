# 产出文档编译系统

## 概述

编译器从状态文件（`expression-audit-state.json`）读取数据，根据当前完成模式生成对应报告。

**核心原则：**
- 产出文档只包含总结和结构化数据，原始问答原文作为独立部分附在末尾
- 快速报告是精简版，核心/深度报告是完整版
- 核心报告和深度报告结构相同，深度报告数据密度更高
- 张力日志必须完整呈现，不能为了整洁而消解矛盾

## 编译流程

```
触发编译
    │
    ▼
读取状态文件
    │
    ▼
根据当前模式选择模板
    │
    ▼
填充模板字段
    │
    │   - Core Identity（基于已答题目的综合概括）
    │   - Quick Reference Card
    │   - Tension Log
    │   - 原始问答（已答题目的完整记录）
    │   - 原型评估（如果数据足够）
    │   - 升级邀请（如果是快速模式）
    │
    ▼
输出报告
    │
    ▼
（可选）写入文件
```

## 编译前的数据准备

在编译之前，必须完成以下数据整理：

### 1. 标记已回答题目的维度标签

遍历 rawData 中所有已回答的题目，为每个答案标记它揭示的维度标签：
- `identity`（身份认同）
- `belief`（信念/价值观）
- `aesthetic`（审美偏好）
- `fear`（恐惧/禁忌）
- `mechanism`（表达机制）
- `audience`（受众关系）
- `contradiction`（矛盾/张力）
- `aspiration`（深层渴望）
- `discernment`（辨别力）

### 2. 总结 Core Identity

基于所有已回答题目中标记为 `identity` 维度的答案，综合生成 2-3 句话的核心身份描述。

**规则：**
- 必须基于具体回答，不能使用模板句式
- 如果数据不足（< 5 题），标记为"初步推断"
- 如果有张力在身份维度上，必须在总结中体现
- 如果 northStarLoop 已完成（currentRound >= 6），参考 candidateNorthStar.direction 作为 Core Identity 的候选输入

### 3. 整理 Quick Reference Card

从 rawData 中提取：
- `always`：被访谈者在多个题目中反复提到的"一定会做的事"
- `never`：被访谈者在多个题目中反复提到的"绝对不会做的事"
- `signatureMoves`：被访谈者独特的表达技巧或习惯

**规则：**
- `always` 最多 5 条，`never` 最多 5 条，`signatureMoves` 最多 3 条
- 每条必须有至少两个题目的证据支撑
- 如果证据不足，减少条目数而不是编造
- 如果 candidateNorthStar 存在，参考 north star 方向补充 signatureMoves

### 4. 整理 Tension Log

从状态文件的 tensionLog 中提取所有未解决的张力，按板块分组呈现。

**规则：**
- 必须完整呈现，不能省略
- 如果某些张力已在后续板块中自然解决，标记为"已解决"
- 快速报告的张力日志只包含最明显的 1-2 条
- 如果 resonanceLog 中检测到共振升级矛盾（如同一人物从 admiration 升级到 identification），记录为张力

### 5. 原型评估（根据锚点状态）

根据锚点状态决定是否包含原型评估：

| 模式 | 锚点状态 | 原型评估内容 |
|---|---|---|
| 快速 | 锚点未触发 | 不包含 |
| 核心 | 锚点 1 完成（L1）| 初步假设，标注置信度 |
| 深度 | 锚点 3 完成（L3）| 最终评估，含主要/次要原型 |

**锚点评估的数据源（更新）：**
- 锚点 1：Q1-Q6 的北极星溯源链 + **resonanceLog**（共振检测结果）+ **resonancePoints**（共振点）
- 锚点 2：D0-D2 数据 + 锚点 1 假设 + D1-D2 张力 + **resonanceLog 升级记录**
- 锚点 3：全部数据 + 锚点 1-2 历史 + 全部张力 + **northStarLoop 结果** + **candidateNorthStar**

### 6. 北极星卡片（North Star Card）

如果 northStarLoop 已完成（currentRound >= 6）或 candidateNorthStar 存在，编译北极星卡片。

**卡片字段：**
- 核心方向（candidateNorthStar.direction，去人名化）
- 我被什么人吸引（resonancePoints 列表，标注共振层级）
- 我反复追求的属性（从 resonanceLog 和 knowledgeGraph 中提取）
- 我不想成为（从 Q12 等禁区题提取）
- 过去的证据（从 Q15 等题提取）
- 未来投射（从 Q18 等题提取）
- 当前 90 天北极星（如果在 northStarHistory 中有最新版本）

**详细规范：** 见 `modules/north-star-discovery-loop.md` 第 3 节

### 7. 影响图谱摘要（Influence Graph Summary）

如果 knowledgeGraph 存在且 nodes 数量 >= 2，编译影响图谱摘要。

**摘要内容：**
- 影响链概览（2-3 层深度的文字描述）
- 共振点标注（哪些节点产生了 strong resonance）
- 素材分层统计（一阶/二阶/三阶素材各有多少）
- 交汇点（如果多条链有共同节点，标注交汇点）

**详细规范：** 见 `modules/knowledge-archeology.md`

### 8. 学习路径推荐

如果 knowledgeGraph 存在且 learningPath 存在，在深度报告中编译学习路径推荐。

**推荐内容：**
- 直接阅读清单（learningPath.directReading）
- 前置阅读清单（learningPath.prerequisiteReading）
- 对比阅读清单（learningPath.comparativeReading）
- 下一步探索（learningPath.nextExploration）

**详细规范：** 见 `modules/knowledge-archeology.md` 第 5 节

## 编译规则

### 通用规则

1. **不做模板化总结**：Core Identity 和 Quick Reference 必须基于被访谈者的具体回答生成
2. **张力日志优先于整洁结论**：保留矛盾，不消解它
3. **原始问答完整保留**：包括追问记录和 depth 标记
4. **原型评估标注置信度**：L1 标注"初步"，L2 标注"较精确"，L3 标注"复核后"

### 快速报告的特殊规则

1. Core Identity 必须标注"基于 10 题初步推断"
2. Quick Reference Card 最多 1-2 条（数据不足）
3. 张力日志最多 1-2 条
4. 必须包含升级邀请
5. 不包含原型评估

### 核心/深度报告的通用规则

1. Core Identity 必须标注"基于 N 题的综合概括"
2. Quick Reference Card 的每条必须有至少两个题目的证据支撑
3. 张力日志必须完整呈现所有跨板块矛盾
4. 原型评估标注阶段（L1/L2/L3）和置信度

### 北极星卡片编译规则

**触发条件：** northStarLoop.currentRound >= 6 或 candidateNorthStar 存在。

**编译逻辑：**

1. **核心方向**：从 candidateNorthStar.direction 读取。如果 northStarLoop 未完成（currentRound < 6），从 Q13、Q14、Q16 的去人名化回答中综合推断，标注"初步推断"。
2. **我被什么人吸引**：从 resonancePoints 读取，按 order 排序（一阶→二阶→三阶），标注每个的共振层级。
3. **我反复追求的属性**：从 resonanceLog 中提取高频出现的品质关键词（跨人物重复出现），合并为 3-5 个。
4. **我不想成为**：从 Q12 的回答中提取。
5. **过去的证据**：从 Q15 的回答中提取 2-3 个案例。如果 Q15 回答不足，从其他题目中寻找自发行为的证据。
6. **未来投射**：从 Q18 的回答中提取。如果 Q18 回答了 Ikigai 交集，将其转化为未来方向描述。

### 影响图谱摘要编译规则

## 升级时的特殊处理

### 快速 → 核心升级

1. 先生成快速报告（基于已有 10 题）
2. 在快速报告末尾展示升级邀请
3. 用户确认后，追加追问已答过的题目
4. 追问完成后，重新编译为核心报告

**升级时的数据传递：**
- 快速模式中检测到的 resonanceLog 完整保留到核心模式
- 快速模式中产出的 knowledgeGraph（如果有）完整保留
- 快速模式的 candidateNorthStar（如果有）完整保留，在核心模式中可能被修正
- northStarLoop 状态（如果有）完整保留，从 currentRound 继续

### 核心 → 深度升级

1. 确认核心报告已完成
2. 告知用户需补充的题数（D3 12 题 + D7 剩余题）
3. 补充完成后，重新编译为深度报告

**升级时的数据传递：**
- 核心模式中完成的所有数据完整保留
- northStarLoop 状态完整保留
- knowledgeGraph 完整保留，在 D3/D7 中可能补充新的节点
- 锚点 1 和锚点 2 的结果完整保留，锚点 3 在深度模式完成后触发
